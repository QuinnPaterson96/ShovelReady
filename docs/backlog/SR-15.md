# SR-15: Deploy immutable builds with migration and rollback controls

Status: Blocked (planning status, not implementation progress)
Milestone: M2: User-tested MVP
Dependencies: SR-14

## Outcome

Automate safe delivery to the demo environment without coupling code and data publication.

## Scope

Extend GitHub Actions to deploy a tested immutable image from main; use short-lived credentials where supported.

## Acceptance criteria

- [ ] Only trusted main/manual release runs can deploy; PR checks have no deployment credentials.
- [ ] Deploy the tested image digest with commit identity; serialize environment changes and prevent older runs overwriting newer ones.
- [ ] Run migrations explicitly once before compatible activation; document backward-compatibility and database rollback limitations.
- [ ] Smoke-test health, UI assets, and a known accepted dataset; a failed rollout leaves or restores a known-good compatible image.
- [ ] Exercise rollback and verify active dataset identity remains unchanged; incompatible code/data combinations are rejected.

## Out of scope

No automatic extraction, data acceptance, or production multi-environment rollout.

## Verification evidence

Successful demo rollout, failed-rollout/rollback exercise, and deployment runbook.

## Open decisions and constraints

Actual CI/CD setup is complete only with verified remote execution, not merely a workflow YAML file.
