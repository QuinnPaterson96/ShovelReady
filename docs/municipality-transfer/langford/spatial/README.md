# SR-44 Langford spatial transfer packet

Captured 2026-09-26 UTC. This is an **unreviewed, offline transfer experiment** for issue #92, not an accepted Langford site or zoning release. It starts from main `6c14d9f` (Civic Atlas merged). The owned files are this directory, `tools/municipality_transfer/langford_spatial.py`, and `tests/test_langford_spatial_transfer.py`. Victoria #86-#89 and shared runtime contracts are unchanged.

## Scope and reproducible packet

Three public address leads were submitted to the official [BC Address Geocoder](https://catalogue.data.gov.bc.ca/dataset/bc-address-geocoder-web-service) `addresses.json` endpoint with `maxResults=3&outputSRS=4326`. Each top point seeded a 0.00001-degree half-width bounded WFS query against the official [ParcelMap BC Parcel Polygons OGL](https://catalogue.data.gov.bc.ca/dataset/parcelmap-bc-parcel-polygons-ogl) view. The six raw JSON responses and exact URLs, UTC capture times, byte counts, SHA-256 hashes and reuse basis are in [manifest.json](manifest.json). Replay verifies bytes before parsing. No owner/contact data, imagery, municipal feature responses or bylaw text is retained. Attribution for these provincial responses: **Contains information licensed under the Open Government Licence – British Columbia.** See [licence v2.0](https://www2.gov.bc.ca/gov/content/data/policy-standards/data-policies/open-data/open-government-licence-bc).

The BC catalogue labels both datasets OGL-BC; its geocoder record describes the separate `/parcels` resource as ministry-restricted, which this packet does **not** call. Provincial [address download guidance](https://dpdd.atlassian.net/wiki/spaces/DATABCKB/pages/1382350915/Downloading%2BBC%2BAddress%2BData) explicitly distinguishes open geocoder *responses* from undistributable reference address data. The PMBC catalogue record `2f4117d9-41fc-44db-87d4-dbdb77f14086` was modified 2026-09-21 and says its OGL polygons are graphical representations, **not** authoritative legal boundaries. These metadata dates are not a per-feature currency guarantee. PMBC's EPSG:3005 coordinates are retained; the WFS query bbox and geocoder points are EPSG:4326. No CRS relabelling occurs.

## Mapping, fallback and limits

Run from repository root:

```powershell
python -m uv run --locked python tools/municipality_transfer/langford_spatial.py
python -m uv run --locked pytest -q tests/test_langford_spatial_transfer.py
python -m uv run --locked ruff check tools/municipality_transfer/langford_spatial.py tests/test_langford_spatial_transfer.py
```

The command is deterministic and offline. It verifies all six hashes, strict JSON, response CRS/count consistency and usable polygon geometry. It transforms the geocoder point to EPSG:3005 and reports unique containing, ambiguous, no-match or unavailable states. Its saved result is a **candidate observation**, not an SR-04 `SiteRevision`: the legal `Geometry` contract accepts a single ring, while PMBC may supply holes/multipart geometry; SR-09 expects Victoria EPSG:3157 and Esri responses. No source area is coerced into regulatory `lot_area`. A future licensed Langford adapter should retain original EPSG:26910, explicit transforms, feature locators, zones and all intersections under a new versioned boundary instead of feeding this packet into Victoria's importer. Shared-file change proposal: add source-scoped address candidate and licensed layer observations to a general spatial intake boundary, keeping ambiguity and source identity visible. No shared change is made here.

The [manual fallback example](manual-fallback.example.json) keeps the PMBC `FEATURE_AREA_SQM=7318.5682 m²` baseline and shows a **simulated**, unreviewed 7300 m² user override on a different stated basis. The override neither replaces the source value nor verifies legal lot area. Manual address alone cannot verify a parcel. Real manual use would require a plan/source locator, original values and units, reviewer, review state and a new immutable revision. Principal building, wall footprint, legal lot lines/rear yard, setbacks, grade/slope, supplied design and placement remain unknown. No legal screening or publication is attempted.

## Verification, effort and handoff

Observed live source access: both provincial endpoints returned 200 JSON and all six bounded queries were saved; Langford metadata was read, feature responses deliberately withheld. Offline checks at this head: `ruff check` passed; focused `pytest` passed **3 tests**; CLI emitted all three cases with `publication_eligible=false`. Tests include actual saved unique/no-match responses and explicitly **simulated** overlapping-PID ambiguity, empty no-match, unavailable source, wrong CRS and tampered hash. No database or model call. No independent parcel, source-rights or legal review, accepted release, user validation or full CI is claimed.

Measured post-branch wall-clock landmarks (UTC): branch at 00:03:06; first permitted capture at 00:04:26; mapper/test files complete at 00:06:18; manual example at 00:07:19. Source discovery after branch to first capture: **1m20s** (earlier source search is unmetered). Adapter plus replay tests from first capture to test file: **1m52s**. Manual correction example construction from test file to example: **1m01s**; this is authoring time for a simulated correction, **not** measured user correction effort. These are lower bounds, not a product timing study.

Integration recommendation: keep Langford expansion exploratory. Provincial geocoder/PMBC can supply a licensed candidate boundary and approximate geometric area; do not present a verified address–parcel result until an authoritative join or independent review resolves the point disagreement. Obtain explicit layer-specific Langford reuse terms and source currency/meaning before retaining its zoning/building/constraint responses. Then repeat three real sites with a reviewed parcel join and independent geometry/legal interpretation; require a distinct data release and source review before any screening. This experiment supports SR-17/#17 but does not close it, change Victoria #86-#89, or launch Langford coverage.
