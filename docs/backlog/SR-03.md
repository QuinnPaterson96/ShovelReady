# SR-03: Establish GitHub Actions CI and required validation checks

Status: Verified on codex/foundation; PR #20 open and unmerged
Milestone: M1: Technical proof
Dependencies: SR-02

## Outcome

Detect broken code and boundary behavior on pull requests without paid model calls or shared databases.

## Scope

Add Python lint/focused tests, frontend type-check/build, disposable PostgreSQL migration checks when migrations land, and safe workflow permissions.

## Acceptance criteria

- [x] CI runs on pull requests and main changes using reproducible dependency installs and supported pinned tooling.
- [x] Every database test uses a disposable job database; no shared cloud credentials or live LLM calls are available.
- [x] Workflow token permissions are minimal; untrusted PR code never receives deployment credentials.
- [x] Required check names and branch-protection setup are documented; enable supported protection or explicitly record account-plan limitations.
- [x] A known failing fixture demonstrates a check blocks success; report only checks actually implemented. Wire later migration/E2E/container suites as they land.

## Out of scope

No elaborate security platform or paid CI service requirement.

## Verification evidence

Successful workflow run plus controlled failing-check evidence and setup documentation.

## Open decisions and constraints

CI provides technical checks, not proof of correct zoning interpretation.
