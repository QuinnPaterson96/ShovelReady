# SR-37: Read-only Pilot preparation investigation

Status: Implemented and integration-verified September 25, 2026; see [wave-nine evidence](../integration-wave-nine.md).
Dependencies: SR-34 diagnostic; independent of SR-36 until final navigation wiring

GitHub issue: https://github.com/QuinnPaterson96/ShovelReady/issues/80

## Outcome

Expose the real Pilot preparation diagnostic as a read-only investigation, keeping
evaluation_not_run separate from an EvaluationReport. A user can inspect observations,
conflicts, source provenance and the specific next evidence needed without a zoning
fit assertion. Reconcile the older public-case wording with the later research.

## Acceptance

- Use the actual SR-34 diagnostic, not another hardcoded JSON summary or evaluator.
  Add a bounded typed GET /api/case-preparations/pilot endpoint with a versioned
  preparation payload; no submitted form inputs, uploads, live model or source fetch.
  Preserve original capture gaps, annotation/source identity distinction and all
  observations/conditions. Serve only the known case, never arbitrary filesystem paths.
- Make runtime packaging honest: do not rely on scripts/ or docs/ being installed in
  the container. If necessary move the reusable diagnostic core into an ordinary app
  module and retain a thin offline CLI. Keep a single canonical input definition or
  a tested explicit packaging/drift boundary. No duplicate maintained rule logic.
- Export a standalone default React component PilotPreparation at
  frontend/src/case_preparations/PilotPreparation.tsx, with no required props. It owns
  its fetch/loading/error/empty states and read-only evidence display. Do not edit
  App.tsx, global navigation/styles or package.json; the integrator wires this route.
  Scope styles locally. Coordinate test-discovery changes with SR-36.
- Prominently state needs investigation / evaluation not run, selected 2018 proposal,
  what mapped, what did not, and actionable next artifacts. Preserve 2.6 m, separate
  0.20/0.22 corners, unresolved 22.25/22.75 area and Plan 5130/5230, and later house
  replacement. Never imply later records establish 2018 geometry or legal applicability.
- Keep details progressive: concise summary first, expandable source-linked reasons,
  quantities/revisions and raw diagnostics. Show missing values explicitly; no green
  zoning result. Do not expose private paths/raw exception text or turn arbitrary
  evidence URIs into executable/download links. Loading/error/reload clears stale data.
- Update the versioned public Pilot inventory's misleading two-drawing-label wording
  to distinguish parsed text from visually confirmed observation and unresolved meaning.
  Cite the later packet accurately, preserve old evidence/history and provisional gates.
  Do not silently assign issued dates or canonical areas from completed permits.
- Backend tests verify parity with the offline diagnostic, actual boundaries and safe
  failures; frontend tests verify uncertainty/provenance display and stale responses.
  Add packaging/endpoint smoke coverage where needed. No shared DB required. All
  existing SR-34 tests must remain meaningful and pass after any module relocation.
