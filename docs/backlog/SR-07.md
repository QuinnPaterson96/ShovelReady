# SR-07: Benchmark and implement bounded LLM-assisted extraction

Status: Blocked (planning status, not implementation progress)
Milestone: M1: Technical proof
Dependencies: SR-04, SR-06

## Outcome

Test whether the existing prompt reduces accepted-rule production effort.

## Scope

Benchmark the current prompt before changing it; add explicit extraction/normalization commands, saved responses, and human review records.

## Acceptance criteria

- [ ] Retain prompt/model/parser/schema identifiers, raw responses, input snapshot identities, and run failures.
- [ ] Measure omissions, applicability, values, unit/ratio bases, evidence, consequential outcome changes, and human correction time against a manual baseline.
- [ ] Malformed candidates are quarantined; semantically unresolved candidates retain evidence and issue status.
- [ ] Prompt changes address observed failures and are evaluated on held-out examples; no generated expression executes as arbitrary code.
- [ ] Report actual live runs and costs separately from offline fixtures; ordinary CI replays saved inputs only.

- [ ] Report baseline counts and consequential error examples plus measured review AND correction time. Do not adopt an arbitrary 95% target or projected hours as observed performance.
- [ ] Preserve actual model responses and model/settings metadata; seed settings alone do not guarantee reproducibility.
- [ ] Separate synthetic validation tests from source-extraction accuracy measurements; reports are evidence leads, not reference truth.

## Out of scope

No fine-tuning, agents, query-time compliance LLM, or benchmark consisting only of valid JSON.

## Verification evidence

Baseline report, empirical error examples, accepted/rejected candidate fixtures, and reproducible evaluation command.

## Open decisions and constraints

Set a bounded live-run budget before execution; human correction time must be measured, not invented.
