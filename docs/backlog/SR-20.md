# SR-20: Verify the native local database lifecycle in Windows CI

Status: Ready for implementation (September 24, 2026)
Milestone: M1: Technical proof support
Dependencies: merged PRs #32/#33; no dependency on SR-21/SR-22/SR-23
Related: SR-03 and SR-13; do not reopen or claim completion of those parent scopes
GitHub issue: https://github.com/QuinnPaterson96/ShovelReady/issues/35

## Outcome

Every PR exercises the actual native database helper's initialize/migrate/seed/restart/API path on Windows. A skipped native lifecycle test must not be reported as verification.

## Scope and acceptance criteria

- [ ] Add a dedicated Windows job with an explicit PostgreSQL 17 binary setup and the repository's Python/uv versions. Verify the binaries instead of assuming a preinstalled service or path; document the selected runner/setup and pin third-party actions by commit.
- [ ] Reuse `tests/test_local_database.py::test_native_lifecycle` and its ownership/refusal checks. Set `SHOVELREADY_LOCAL_LIFECYCLE_POSTGRES_BIN` explicitly. Run only against a fresh temporary cluster and available loopback port, never the manual persistent database or an installed database service.
- [ ] Preserve initialize, idempotent migrate/seed, stop/restart retention, exact revision/source retrieval and real `/api/investigation` verification. Preserve existing Linux service-database tests.
- [ ] Fail clearly for missing binaries, no selected tests or an unexpected lifecycle skip. Demonstrate the skip guard fails using an isolated controlled invocation; do not leave an intentionally broken check in the PR.
- [ ] Stop only the owned scratch cluster even on failure; keep diagnostics useful without uploading passwords, `local.json`, database contents or raw connection strings.
- [ ] Record an actual successful Windows CI run and exact command/test/skip evidence. Run the job on all PRs initially so path filtering cannot silently bypass a future required check.
- [ ] Propose a stable required-check name in the handoff. Changing branch protection belongs to integration after the job passes; do not bypass existing required checks or change repository settings independently.

## Ownership and exclusions

Own `.github/workflows/ci.yml`, focused lifecycle test/guard support and `docs/ci-local-database.md`. Read but avoid changing `scripts/local_database.py` unless a demonstrated defect requires a narrowly explained fix. SR-21 owns demo scripts and `docs/local-development.md`; SR-22 owns PR templates/AGENTS/quality handoff text. Leave shared dependency/lockfile changes to explicit coordination. No cloud deployment, paid services, broad OS matrix or live model calls.

## Delivery

Use branch `codex/native-lifecycle-ci` in this task's managed worktree. Verify personal author/committer and both Git/gh authentication before writes. Commit explicit paths, push and open a reviewable PR against main; do not merge or close related parent tickets. Describe exact evidence, skips and remaining limitations. Central README/backlog reconciliation belongs to integration.
