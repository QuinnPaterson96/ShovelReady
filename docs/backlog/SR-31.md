# SR-31: Run the bounded virtual-user pilot and assess its value

Status: Complete as a bounded experiment; reviewed decision is narrow to on-demand use (September 24, 2026)
GitHub issue: https://github.com/QuinnPaterson96/ShovelReady/issues/55
Milestone: M1 support
Dependencies: SR-26 evidence reviewed; SR-28, SR-29 and SR-30 integrated
Related: SR-13 preparation; does not satisfy SR-06 or SR-16

## Outcome

Determine whether a small repeatable browser-agent evaluation produces useful,
reproducible findings at an acceptable review cost before expanding or scheduling it.

## Acceptance criteria

- [x] Freeze a pilot manifest identifying the merged app, data/fixtures, case/rubric
  versions, participant/tool configuration, execution adapter, case selection and
  budgets. Review control validity and current SR-26 findings first. Reserve untouched
  groups for later evaluation; never call already tuned cases holdouts.
- [x] Run up to five scenarios twice each in ordinary task mode, plus three paired
  clean/fault examples in explicit detection mode: at most 16 fresh participant sessions,
  sequentially, ten minutes or 60 browser actions each. These are ceilings, not a quota.
  Record actual actions/times and unavailable cost metadata; no new paid service is
  authorized without a configured project and explicit spending limit.
  Applied the allowed narrowing decision after six detection sessions. The ordinary-task
  arm was not run; completion here does not claim those ten planned sessions occurred.
- [x] Each participant has a fresh context containing only its brief/URL/necessary browser
  constraints. Use the actual rendered app, not an API substitute or the answer rubric.
  No coaching, code inspection or silent rerun after feedback. Record practical isolation
  limits. Stop rather than fabricate a pass if proper browser access is unavailable.
- [x] Retain original notes, action traces, evidence pointers, completion/timeout/blocked
  outcomes and environment cleanup evidence. Grade only after the original attempt;
  preserve corrected rubrics/grades separately. Review disputed or consequential findings
  against recorded evidence before attributing a defect to the application.
- [x] Reproduce confirmed defects after the blind attempt. Prepare deduplicated issue
  drafts with acceptance criteria and the smallest meaningful deterministic regression;
  classify omissions, source gaps and usability hypotheses separately. No automatic app
  patching or issue publication within the participant loop.
  Three seeded variants were reproduced; no baseline defect required a ticket or regression.
- [x] Report counts/denominators, detected known faults, clean-control false alarms,
  unsupported conclusions, critical omissions, environment failures and actual review
  effort. Separate authored controls from real observational cases and participant
  ability from app correctness. Do not infer population accuracy or human satisfaction.
- [x] Make an explicit continue/narrow/stop recommendation based on finding usefulness,
  reproducibility and review cost. Identify the next one or two changes only if supported
  by evidence. Stop early for unsafe ownership, unusable evidence or unreliable grading;
  document the blocker. No bugs found is a valid result, not a reason to invent tickets.
- [x] Hand confirmed findings to the integrator for issue creation and regression work;
  propose only offline checks for ordinary CI. Keep live runs advisory and on demand.
  Cloud scheduling, automatic ticketing and a results database remain deferred.
