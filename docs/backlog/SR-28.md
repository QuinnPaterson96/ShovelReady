# SR-28: Assemble five virtual-user scenarios and paired defect controls

Status: Complete in bounded fixture scope; PR #59 merged (September 24, 2026)
GitHub issue: https://github.com/QuinnPaterson96/ShovelReady/issues/52
Milestone: M1 support
Dependencies: SR-27; SR-24/SR-25 are optional inputs only after integration/review
Related: SR-06, SR-19, SR-26; see [evaluation plan](virtual-qa-plan.md)

## Outcome

Supply a small test library with inspectable expected behavior, including clean
examples that prevent a bug-seeking agent from succeeding merely by reporting problems.

## Acceptance criteria

- [x] Define five bounded scenarios using existing licensed observations and explicitly
  synthetic preview cases where possible: VIC-080 evidence/unknowns; a coherent synthetic
  candidate; a bounded negative result that must not imply universal site exclusion;
  conditional or incomplete evidence; and provenance/revision correction. Verify actual
  available fixtures before finalizing categories; disclose substitutions and gaps.
- [x] Each scenario conforms to SR-27, has a neutral task brief, separately held rubric,
  exact fixture/source identities, observer-visible supporting evidence, expected
  qualifications and prohibited overclaims. An expected outcome can be "cannot
  establish this". Avoid making completeness depend on undisclosed legal facts.
- [x] Add three deliberately faulty variants, each paired with a reviewed clean control.
  Prefer one isolated fault per variant: missing evidence link, visible source/display
  unit inconsistency, or an unsupported affirmative label replacing an unknown state.
  Review that the specific fault is observable from the browser and the pair differs
  only as intended. Mark control truth as authored software behavior, not zoning truth.
- [x] Provide deterministic variant recipes/assets and expected content hashes for the
  runner. Keep variants in disposable local fixtures/builds; never mutate accepted
  sources, releases or the user's database/preview. Identify any derived build/overlay
  separately from the baseline commit; do not bypass the launcher's clean-tree check.
  Coordinate the minimal materialization boundary with SR-29 before adding hooks.
- [x] Preserve original fixtures. No fault injection switches or facilitator rubrics ship
  in the ordinary app bundle. No application improvement is bundled with the test pack.
- [x] Record review evidence for clean controls, source licensing, known limitations and
  grouping of related cases. Development/calibration and reserved groups are explicit;
  a case used for tuning is no longer an untouched holdout. Public historical packets
  remain provisional unless SR-06's independent review has actually occurred.
- [x] Offline checks verify contract validity, referential integrity, paired differences
  and unchanged baseline bytes. Document a facilitator browser review of controls;
  record unavailable checks honestly rather than claiming perfect ground truth.
