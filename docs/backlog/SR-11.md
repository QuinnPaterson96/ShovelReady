# SR-11: Publish reviewed data atomically and derive scouting projection

Status: Blocked - extraction/review, persistence and evaluator gates remain (checkpoint: 2026-09-24)
Milestone: M1: Technical proof
Dependencies: SR-07, SR-08, SR-10

## Outcome

Make scouting a reproducible projection of accepted detailed rules while protecting the active release.

## Scope

Add draft validation, explicit review/acceptance, immutable release manifests, projection generation, and atomic activation.

## Acceptance criteria

- [ ] Release identifies exact source/rule/spatial/design-compatible schema and projection/evaluator versions and declared coverage.
- [ ] Only accepted supported semantics drive determinate checks; unresolved issues remain explicit in coverage/results.
- [ ] Publication validates corpus outcomes and reports changed decisions before activation.
- [ ] Failed import/projection/publication leaves the active release intact; competing activation attempts cannot partially mix releases.
- [ ] An earlier dataset can be reselected and its results reproduced with compatible evaluator code; deploying code does not activate new data.

- [ ] Release manifests/results identify site-fact and placement revisions as well as rule/data versions. Decision diffs distinguish placement/input corrections from regulatory changes.
- [ ] Publication regression cases reject wrong-era rules and retain outside-coverage/missing-input states without falsely promoting them to passes or prohibitions.

## Out of scope

No queue, continuous automatic acceptance, or model-confidence publication gate.

## Verification evidence

Successful and deliberately failed publication tests; two releases with an explained correction.

## Open decisions and constraints
