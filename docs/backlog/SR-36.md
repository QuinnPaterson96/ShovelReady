# SR-36: Home, parameter entry and clear assessment status

Status: Ready for implementation (wave nine)
Dependencies: Existing main; independent of SR-37 until final navigation wiring

GitHub issue: https://github.com/QuinnPaterson96/ShovelReady/issues/79

## Outcome

Replace the developer-first mode selector as the default landing experience with
Home -> Assessment inputs -> Preparation/result summary. Preserve all existing
observation, public-case, authored-preview and computed-draft views under an obvious
Examples/evidence route. Build a restrained, accessible visual baseline, not a large
branding exercise or new frontend stack.

## Acceptance

- Home explains the supported decision and offers Start an assessment and Explore
  examples. Technical build/health identities move into a secondary panel.
- The assessment form is primary; no example is selected automatically. Include
  municipality, intended use/building role and optional width/depth/height/floor-area
  inputs with explicit metres/m2. Site/placement facts can remain unknown. Distinguish
  empty, invalid and known values; reject nonfinite/negative or impossible values with
  useful field errors, without converting blanks into zero. Do not invent legal limits.
- Load an example is an explicit action. Offer clearly labelled existing synthetic
  examples using a documented mapping from their actual request inputs. Do not imply
  their fixture review applies to user edits. Retain original imported values/source
  identities alongside edited values and label edits user supplied. Confirm before
  replacing a dirty draft. Pilot's conflicting observations must not be silently
  selected as canonical editable parameters; link to its investigation separately.
- Submission produces a preparation summary, not fabricated EvaluationRequest or
  acceptance. A complete form is not evidence of zoning fit. Untouched/unassessed
  is grey; missing/unreviewed evidence is amber; unsupported geography is neutral
  outside scope. No arbitrary form entry can generate a green/red regulatory result.
- Add a reusable accessible StatusBanner: explicit label + colour/icon + reason,
  checks/coverage, unresolved items and next action. Support neutral not-assessed /
  outside-coverage, amber needs-investigation, green scoped candidate and red failed
  supplied placement. Green/red are only for actual supported results and synthetic
  examples are visibly labelled. Keep approval distinct. Do not map request failure
  or outside coverage to prohibition. Health status must not be mistaken for assessment.
- Preserve draft values when moving between home/input/summary during this session.
  Editing invalidates any prior result and import edits cannot reuse the original
  computed fixture result. No accounts, server persistence or localStorage needed.
- Meaningful tests cover empty/invalid input, unit display, explicit import/replacement,
  retained provenance, edit invalidation and status mapping. Verify keyboard labels,
  narrow layout, contrast and existing routes. Run frontend checks/build; document
  actual browser verification separately from static rendering tests.

## Ownership and handoff

Own frontend/src/App.tsx, application navigation/home/form modules, shared StatusBanner
and appropriately scoped styles/tests; own frontend/package.json test discovery only
if needed. Do not modify Pilot component/API/core or central research inventories.
Preserve existing inspector semantics and endpoints. Prefer existing React state and
small modules over a router/form/state library unless a concrete need emerges.

SR-37 independently exports default PilotPreparation from
frontend/src/case_preparations/PilotPreparation.tsx, with no required props. Leave
that route's final import/wiring to integration if its PR is unavailable; build cleanly
without nonexistent imports. Document the intended navigation hook. Coordinate rather
than editing SR-37 files. No manufactured placeholders presented as real data.

Read AGENTS, README, architecture, quality, wave-nine handoff, draft-evaluation UI
docs and existing source views. Open a PR, do not self-merge. Parent SR-12 remains open.
