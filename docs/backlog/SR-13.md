# SR-13: Verify source-to-result behavior and package one deployable image

Status: Partial - container and database lifecycle checks integrated; accepted source-to-result path remains open (wave 4 integration: 2026-09-24)
Milestone: M1: Technical proof
Dependencies: SR-03, SR-12

## Outcome

Demonstrate the complete system and make the same build deployable.

## Scope

Create an offline integration fixture from saved extraction through persistence, publication, evaluation, and evidence retrieval; package FastAPI plus built frontend.

## Acceptance criteria

- [ ] CI runs the fixture against isolated PostgreSQL and checks source/rule/release identities at the UI/API boundary.
- [ ] A malformed extraction and failed data publication leave the last accepted result usable.
- [ ] Container starts with explicit configuration, serves API and frontend, and reports health without exposing secrets.
- [ ] Build records commit/image identity; runtime runs with least necessary privileges and source artifacts are not stored only on ephemeral disk.
- [ ] Document exact local demonstration and container smoke-test commands.

- [ ] Include an offline end-to-end case with a versioned proposed placement and manual site facts. Verify those identities survive API/UI serialization.
- [ ] Exercise outside coverage, missing required facts, historical-source rejection, and a failed placement without a universal parcel exclusion; no live model calls are introduced.

## Out of scope

No paid/live extraction in PR CI or deployment-specific branching of application behavior.

## Verification evidence

Green integration and container smoke checks, image identity, and demonstration instructions.

## Open decisions and constraints

Extend SR-03 rather than creating a second independent CI pipeline.
