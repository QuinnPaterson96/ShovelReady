# SR-03: Establish GitHub Actions CI and required validation checks

Status: Blocked (planning status, not implementation progress)
Milestone: M1: Technical proof
Dependencies: SR-02

## Outcome

Detect broken code and boundary behavior on pull requests without paid model calls or shared databases.

## Scope

Add Python lint/focused tests, frontend type-check/build, disposable PostgreSQL migration checks when migrations land, and safe workflow permissions.

## Acceptance criteria

- [ ] CI runs on pull requests and main changes using reproducible dependency installs and supported pinned tooling.
- [ ] Every database test uses a disposable job database; no shared cloud credentials or live LLM calls are available.
- [ ] Workflow token permissions are minimal; untrusted PR code never receives deployment credentials.
- [ ] Required check names and branch-protection setup are documented; enable supported protection or explicitly record account-plan limitations.
- [ ] A known failing fixture demonstrates a check blocks success; report only checks actually implemented. Wire later migration/E2E/container suites as they land.

## Out of scope

No elaborate security platform or paid CI service requirement.

## Verification evidence

Successful workflow run plus controlled failing-check evidence and setup documentation.

## Open decisions and constraints

CI provides technical checks, not proof of correct zoning interpretation.
