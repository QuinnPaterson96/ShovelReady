# SR-24: Inspect provisional public case evidence in the application

Status: Ready for implementation (September 24, 2026)
GitHub issue: https://github.com/QuinnPaterson96/ShovelReady/issues/44
Milestone: M1: Technical proof preparation
Dependencies: merged PR #43 and existing investigation UI; independent of SR-25/SR-26
Related: SR-12; does not complete accepted screening

## Outcome and scope

Make the ten provisional research packets usable for investigation inside the existing
application. Start with VIC-PC-001 (Stannard) and a selector for the existing inventory;
do not infer site geometry or link it to the three different licensed spatial leads.

## Acceptance criteria

- [ ] Add a bounded read-only API and separate public-case investigation mode using the
  committed `docs/research/public-cases/cases.json`. Use typed versioned boundary data
  and an inventory content/revision identity, explicitly distinct from accepted dataset
  releases. Validate the selected inventory and fail clearly on malformed/missing data.
- [ ] Show case/jurisdiction, historical status/dates, plan versions, original reported
  measurements and units, evidence locators/links, conditions, conflicts and missing
  inputs. Keep source facts, official interpretations and researcher inferences distinct.
  Preserve unknowns and provisional review status; do not turn a plan's listed limit
  into an accepted zoning rule or a measurement into a verified fact.
- [ ] Clearly state no screening or current prefab-fit result. Label Saanich/Vancouver
  cases as transfer examples. Identify the public-case inventory separately from the
  spatial observation revision and the fictional preview.
- [ ] Serve only explicit safe DTO fields and source links to the observed official
  HTTPS hosts. No local paths, arbitrary file access/URL fetches, credentials, unsafe
  HTML, runtime scraping or source-PDF republication. Do not invent source access when
  external links are unavailable. This mode should work without a configured database.
- [ ] Include only required metadata in the app/container package; no PDFs or temporary
  inspection files. Keep one application and existing stack, with no database migration
  or generalized case-management framework.
- [ ] Test normal inventory mapping and material failure cases: duplicate/broken source
  references, missing/unknown measurements, provisional status preservation and unsafe
  links/text. Verify the actual built view and existing modes. Run relevant backend,
  frontend and container checks; document exact head, commands and limitations.

## Ownership and delivery

Own a focused `app/reference_cases/` adapter/router, its tests, frontend case components
and mode wiring, narrowly needed `app/main.py`/Docker packaging and
`docs/reference-case-view.md`. Read the inventory but do not modify it: SR-25 writes a
separate historical review packet. SR-26 tests a frozen pre-change demo in another
worktree. CI, shared dependencies and central docs remain integration-owned unless a
concrete defect justifies coordination. Use `codex/public-case-view`, commit/push with
verified personal identity and open a PR without merging or closing parent SR-12.
