# SR-42 Saanich parcel and site transfer packet

Captured September 25, 2026 from the District of Saanich's [Data Catalogue](https://www.saanich.ca/EN/main/local-government/data-catalogue-1.html). This is an **unreviewed, bounded offline experiment** for issue #90, using three public civic addresses. It is not a municipal launch, a legal site determination, or an accepted spatial release.

## What was retained and how to replay

`capture.json` holds the exact selected civic-address CSV field values and source-indexed shapefile attributes and geometry converted to GeoJSON by pyshp 3.1.6. It is an excerpt, not the original ZIP bytes or an Esri API response. `manifest.json` records the five official download URLs, archive byte counts and SHA-256 hashes, member hashes, capture hash, date, licence, and attribution. Full downloaded ZIPs were used in a local temporary directory and were not committed. Source record indexes locate rows within those specific archives; they are not permanent feature IDs. The source files contain their metadata PDFs and the same licence PDF. No owner/contact fields were retained. This packet makes the original source values and derived computations distinguishable. The original capture and manifest remain unchanged after the SR-46 topology audit; `zoning-topology-v2.json` is a separate derived revision.

Observed whole-file coverage at capture: 32,965 civic-address rows, 9,114 sub-address rows, 42,924 parcel records, 1,890 zoning records, 62,320 building records, and 6,151 watercourse records. The replay retains only three civic rows, three parcels, four zoning records, seven rooflines, and one nearby watercourse. These counts establish file coverage, not completeness or date of last feature update.

```powershell
python -m uv run --locked python tools/municipality_transfer/saanich_spatial.py '3325 KINGSLEY ST'
python -m uv run --locked python tools/municipality_transfer/saanich_spatial.py '4225 CEDAR HILL RD'
python -m uv run --locked python tools/municipality_transfer/saanich_spatial.py '2150 FOUL BAY RD'
python -m uv run --locked pytest -q tests/test_saanich_spatial_transfer.py
# With the independently downloaded, hash-matching original archive only:
python -m uv run --locked python tools/municipality_transfer/saanich_spatial.py --audit-zoning-archive C:/Temp/shovelready-sr46/ZoningSHP.zip
```

The command verifies the capture hash and version, uses only saved local input, and emits a versioned JSON observation. It requires the repository's existing Shapely dependency. Matching requires one exact civic-address CSV row, a parcel with the same address string, and that address point covered by the parcel polygon in EPSG:3157. Multiple candidates are retained as `ambiguous`; no exact match is `no_match` **only within this three-address excerpt**; missing required source layers are `unavailable`. These statuses are not permission or buildability decisions. PID and parcel subtype are retained, while the civic `FACILITYID` and source index identify evidence. No address or PID join alone establishes title, survey accuracy, parcel assembly, or principal-building identity.

## SR-46 original-source topology audit

On September 25, 2026, `ZoningSHP.zip` was reacquired from the permitted catalogue URL. Its SHA-256 was `57fac42fd00803e8cd04ac7e00db6a40090b998d0ae28d2353fe9546fd64ce73`, exactly the retained manifest value. The `Zoning.shp` member also matched its manifest hash. The audit reads raw SHP polygon part offsets and XY doubles, compares all 108 source rings in part order against the flattened retained GeoJSON rings, computes orientation from signed XY area, and checks each ring and captured polygon with Shapely 2.1.2. Every coordinate and part matched exactly. Each selected record has a clockwise exterior followed by counterclockwise holes. This evidence identifies source-ring defects rather than a demonstrated conversion defect. No geometry repair or new coverage was applied.

| 1790, `RS-6` | 15: one clockwise exterior, 14 counterclockwise holes | Exterior part 0 and hole parts 12 and 14 self-intersect; see the revision for coordinates | Foul Bay: possible envelope contact; `geometry_unusable`, area `null` |

The versioned [`zoning-topology-v2.json`](zoning-topology-v2.json) records the input capture, ZIP and SHP hashes, exact-match results, each part's orientation and validity diagnostic. The CLI audit command reproduces that revision when given the original archive; ordinary CI uses the saved derived revision and synthetic hole, multipart and invalid-geometry controls, without live downloads. For invalid polygons the replay now checks only envelope overlap, reports a **possible** contact, and leaves area `null`; it does not run a polygon intersection or interpret a boundary. Thus zone contact coverage remains **not computable** for Kingsley or Foul Bay, and only the valid `RS-10` overlap is computable for Cedar Hill. Cedar Hill's possible `RS-6` contact prevents an exhaustive zone coverage claim. No overlap establishes legal applicability.

Upstream clarification is needed from the District of Saanich's zoning data owner for records 1853, 1659 and 1790: corrected valid source geometries or an authoritative explanation of intended ring topology and which zones cover these three parcels. Until then, quarantine those record indexes for area/coverage calculations. Reacquire and pin any corrected source as a new revision; do not infer coverage from the valid fragment or use `buffer(0)`/`make_valid` as a silent legal fix.

The parcel XY areas are planar computations from extracted polygons. Saanich's `AREASQM` is a separate original field with a ground level scale factor. The two quantities have different bases and must not silently replace one another. A roofline follows eaves and is not a surveyed wall footprint. The watercourse distance is to a mapped line, not a legal stream boundary. No negative finding about other constraints is possible from this narrow excerpt.

## Mapping limits and manual fallback

The existing Victoria `sr-09.v1` spatial import expects hash-pinned raw Esri feature responses and assessed intersections. This packet originates from catalogue ZIPs, so it cannot be inserted into that contract by relabelling derived GeoJSON as an original Esri response. The current `SiteRevision` requires explicit parcel, principal-building, lot-line and rear-yard facts with provenance; it accepts a simple single-ring polygon as a known geometry. These parcel observations are not reviewed legal site facts, and complex geometry would need a contract decision. No shared contract, importer, evaluator, API or UI was modified.

Manual fallback example for the Kingsley candidate: start with the source baseline `{field: parcel_area, original_value: 518.3, unit: m2, basis: Saanich AREASQM ground-level scale factor, origin: ParcelsSHP.zip / Parcels.dbf / source record 9634, review_status: unreviewed}`. A researcher might enter `{field: parcel_area, override_value: 520, unit: m2, basis: applicant-supplied approximate area, origin: manual entry, reason: illustrative correction pending survey, review_status: unreviewed}`. Preserve **both** values and their bases; do not replace the baseline, publish the override, or mark the parcel verified. A typed address without the point and polygon corroboration remains an unverified address lead. The example override is simulated and was not used by the replay.

## Decision and effort

Recommendation: reuse the Victoria observation/revision design but add a distinct catalogue-file acquisition adapter with original archive/member hashes, a source-row locator and explicit field-name/CRS mapping. Keep ambiguous/no-match/unavailable states and source-invalid zone geometry unresolved. Add an independently licensed, reviewed constraint source before any absence-of-constraint finding. Require human review of parcel identity, zoning boundary/bylaw applicability, building roles, title and source currency before linking to a `SiteRevision`; publication stays separate from code deployment. Do not block Victoria #86–#89 on this experiment.

Measured task-session effort, rounded to minutes: source discovery and licence/metadata inspection **~8 min**; archive acquisition, excerpt selection and adapter/replay work **~5 min**; manual correction and review **0 min performed** (the fallback above is illustrative). These are development wall-clock observations, not a measured production per-parcel throughput. Automated mapping of all three captured candidates takes under a second locally; independent field verification remains unmeasured.

Remaining gates: official live geocoder capability, source dataset release dates versus metadata update cadence, stable address-to-parcel joins across updates, map-only overlay permissions, invalid zoning topology, legal instrument/parcel interpretation, independent source and site review, accepted release, and user validation. The simulated ambiguous/no-match/unavailable tests are failure controls, not claims that those cases occurred in the three live-source selections.
