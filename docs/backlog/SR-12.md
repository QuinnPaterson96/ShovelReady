# SR-12: Expose screening and evidence in API and thin investigation UI

Status: Blocked (planning status, not implementation progress)
Milestone: M1: Technical proof
Dependencies: SR-10, SR-11

## Outcome

Let a user inspect why a real design/site pair is retained, excluded, or unresolved.

## Scope

Add typed screening/evidence endpoints and a simple React design selector, sample parcel selection, results, and source inspection.

## Acceptance criteria

- [ ] Input validation rejects malformed requests; result serialization retains units, pathway, uncertainty, rule IDs, and release identity.
- [ ] User can inspect checked facts, missing facts, scope exclusions, supporting clauses, and source/retrieval dates.
- [ ] Candidate, investigation, and scoped exclusion are distinguishable without color alone; no unsupported buildable/approved label.
- [ ] Screen a batch of selected parcels with the same core evaluator as a single parcel; a small map/GeoJSON view is sufficient.
- [ ] Source document or extracted text renders as inert content; writes and ingestion are not public endpoints.

- [ ] Display the exact supplied placement and reviewed site inputs used; clearly label failed-placement results without implying that every placement fails.
- [ ] Display outside supported coverage separately from evidenced exclusions. Show missing grade/model facts and manual/provisional inputs without misleading green map labels.
- [ ] No automatic site-layout search or interactive BIM/placement editor is required; selecting saved reviewed placements is sufficient.

## Out of scope

No unrestricted citywide address search, generative massing, BIM editor, or public commercial API product.

## Verification evidence

API contract tests and a recorded walkthrough covering all three outcomes.

## Open decisions and constraints

Start with reliable parcel IDs/sample selection; add address resolution only if the pilot workflow needs it.
