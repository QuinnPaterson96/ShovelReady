# SR-04: Define typed boundaries for sources, designs, rules, and results

Status: Ready (planning status, not implementation progress)
Milestone: M1: Technical proof
Dependencies: None

## Outcome

Make uncertainty and semantic meaning survive ingestion, storage, evaluation, and display.

## Scope

Create versioned Pydantic contracts from existing prompt examples and report findings; refine against the corpus before freezing v1.

## Acceptance criteria

- [ ] Valid and invalid fixtures cover source snapshots, fixed design revisions, rule candidates/revisions, site facts, release references, and evaluation results.
- [ ] Separate geometric from regulatory measurements; normalize dimensions and ratio bases while preserving source values.
- [ ] Represent extraction failure, missing facts, unsupported logic, not applicable, and unresolved references distinctly.
- [ ] Source locator, logical rule identity, immutable revision identity, and schema version remain separate; effective dates may be unknown.
- [ ] Coherent pathway and approval/scope information can accompany candidate, investigation, and scoped exclusion results.

- [ ] Represent a versioned proposed placement and its coordinate reference, principal-building geometry, classified lot lines, and reviewed rear-yard boundary; each manual fact retains evidence, reviewer status, and uncertainty.
- [ ] Distinguish a failed supplied placement from a design-wide or parcel-wide exclusion. Outside supported coverage is not a zoning failure.
- [ ] Retain manufacturer interior area, nominal exterior dimensions, regulatory floor area, and occupancy footprint as distinct quantities. Do not infer roof height from ceiling height.

## Out of scope

No universal expression language, BIM schema, or speculative vendor adapter framework.

## Verification evidence

Schema examples and meaningful validation/serialization tests.

## Open decisions and constraints

Keep unfamiliar rule forms unresolved instead of expanding ontology speculatively.
