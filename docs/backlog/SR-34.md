# SR-34: Prepare a reproducible historical Pilot intake diagnostic

Status: Implemented in PR #78; merged September 25, 2026
Milestone: M1 preparation; supports SR-05/06/10/13 without completing them
Dependencies: Merged Pilot packet and existing contracts/evaluator; independent of SR-35

GitHub issue: https://github.com/QuinnPaterson96/ShovelReady/issues/74

## Outcome

One offline command attempts an honest mapping of the frozen July/August 2018 Pilot
proposal into current typed inputs and reports reproducible, source-linked blockers.
This is an executable case-preparation experiment, not another prose gap inventory
or a manufactured accepted zoning result.

## Scope and acceptance

- [ ] Read the merged Pilot packet, integration review, current SR-04/SR-10 models
  and evaluator before choosing the smallest adapter. Preserve the 2.6 m observation,
  uncertain historical 2.4 m rule/definition, 0.20/0.22 m corner observations,
  22.25/22.75 m2 conflict, Plan 5130/5230 conflict and later house replacement.
- [ ] Pin case, selected design/placement period, input annotation revisions and
  source identities. Later permit/listing evidence cannot silently supply 2018
  dimensions or law. Label manually authored research observations accurately.
- [ ] Use existing types for quantities, references and input fragments where
  truthful. Missing snapshot hashes/times, geometry, accepted rule revisions or
  reviewer attestations remain absent/uncertain; do not fabricate them to pass a
  validator. A hash of our research annotation is not a hash of the municipal source.
- [ ] Produce deterministic machine-readable and concise human-readable diagnostics:
  what mapped, what failed validation, what remains missing or unsupported, exact
  supporting source/locator, and the next required artifact for each relevant gap.
  If the evaluator cannot honestly be invoked, explicitly say evaluation was not run;
  do not wrap a preparation failure in a fabricated EvaluationReport.
- [ ] Attempt existing boundary validation and, only if a truthful request is
  representable, the existing evaluator. Preserve all conditions/references and
  missing revisions. Never construct AcceptedRuleRevision with invented acceptance.
  Document the concrete schema/semantic obstacle instead of weakening its gate.
- [ ] Add focused behavioral tests for the observed risks: stale replacement-house
  evidence mixed with the 2018 placement, unresolved parcel identity, conflicting
  area observations, and missing acceptance/source evidence. Test data loss and
  inappropriate evaluation, not merely hardcoded output strings. No live network,
  model calls or shared database in ordinary tests.
- [ ] Document one runnable offline demo, actual observed output, verification and
  the smallest proposed next change justified by this case. No positive result is
  required. Keep acceptance/publication/customer validation separate.

## Ownership and constraints

Own a small case-specific adapter/CLI (prefer scripts/diagnose_pilot_case.py or an
equally small ordinary module), its focused tests, a task-owned Pilot input annotation
under docs/case-diagnostics/pilot/, and docs/case-diagnostics/README.md. Inspect project
test/lint discovery and wire in only what those files need. No changes to evaluator
semantics, shared contracts, persistence, HTTP aliases, UI, CI architecture or central
research inventories. Shared-interface proposals go in the handoff, with the observed
failure. No generic rules engine, new data service or acceptance flags.

The research packet is usable for this experiment before the whole site's history
or eventual construction is proven. A historical proposed-placement test does not
establish current permission or a prefab fit. Existing public-case and synthetic APIs
stay unchanged. Do not copy private source bytes into fixtures.

Deliver a PR with the exact base/head, demo command, verification and remaining gates.
Follow AGENTS.md, docs/quality.md and the [wave-eight handoff](wave-eight-prompts.md).

## Delivery

The offline diagnostic maps five uncertain fragments, retains eight observations and
reports actual source/acceptance boundary failures. [Integration evidence](../integration-wave-eight.md)
records tests and the browser limits. SR-37 owns the subsequent API/UI bridge; this
delivery does not close the parent accepted-data objectives.
