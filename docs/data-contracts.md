# SR-04 provisional data contracts

These Python/Pydantic boundaries describe the first source-to-result wire payloads. They are provisional until SR-01/SR-05 provide the actual design, current applicable regulations, and reviewed site/placement inputs, and SR-06 provides a clause corpus. The only retained source artifact used in the test fixture is the repository's original [extraction prompt](../app/prompts/document_parsing), whose bytes are hashed at test time. Its numeric examples are **not** legal rules. Geometry, reviewer names, approval, and a 45% limit in the fixtures are synthetic and do not claim Victoria or Vancouver applicability. The [restart assessment](restart-assessment.md) identifies specific Vancouver R1-1 provisions and a source URL, but SR-04 has not pinned or re-reviewed that source; those observations remain evidence leads.

## Boundaries and semantics

`app.contracts` keeps Pydantic models independent of FastAPI, persistence, and the legacy upload schema. `schema_version = sr-04.v1-provisional` is mandatory on each root payload. Unknown fields and unsupported versions fail validation. Decimal values serialize as decimal strings. Source capture time and legal effective time are distinct; effective dates require their own evidence. An artifact identifies retained bytes by URI and SHA-256, while an evidence locator identifies the supporting passage and context. Schema validation checks presence and consistency, **not** whether that passage supports the interpretation.

Design, site, placement, and accepted-rule payloads carry logical IDs and separate revision IDs. They do not invent revisions from section numbers or content hashes. Design measurements distinguish manufacturer interior area, nominal exterior dimensions, occupancy footprint, regulatory floor area, ceiling height, roof height, and regulatory height. A missing regulatory area or roof height stays missing. Quantity retains original text, value, and unit alongside normalized value and unit. Percent is a fraction (45% → 0.45) with a named numerator and denominator; FSR 1.2 is 1.2 with its own basis. Only unit conversions are automatic; area-accounting definitions and datum choices require review. `m`, `ft`, `m2`, `ft2`, counts, fractions, and spaces/unit form the initial allowlist. Other units and dimensions require an explicit schema revision.

Site geometry records parcel, principal building, classified lot lines, and reviewed rear-yard boundary independently, each with evidence, review state, and uncertainty. Missing or uncertain geometry is explicit. Placement is an immutable supplied-footprint revision referencing exact site and design revisions, with its CRS. The bundle validator checks placement/site CRS equality but makes no topology, slope, or legal-yard inference. Geometry validity beyond a basic ring/line check awaits reviewed pilot data and a spatial implementation.

The original prompt's scalar, threshold, category, comparison, and external-reference forms remain useful extraction examples. Its `45 or 0.10 for 10%` wording, `N/A`/`uncertain` strings, and multiple top-level objects cannot safely be interpreted as this contract. SR-07 should retain the raw prompt output, map only unambiguous values into candidates, and record failures/ambiguity instead of silently converting them. Only reviewed scalar bounds with explicit operators and compatible quantity bases are eligible for `runtime_support=supported`. Threshold boundaries, greater/lesser calculations, discretion, other conditions, and references to absent schedules can be retained as non-executable `unresolved` semantics with evidence and reason. This is an intentionally small rule shape, not a rule language.

Each rule belongs to a named pathway and alternative. A dataset pins source snapshots, accepted rule revisions for coherent alternatives, spatial versions, projection version, and evaluator version. Results must account for all declared alternatives using only their released rule revisions and source evidence. Distinct check states include `missing_fact`, `extraction_failure`, `outside_coverage`, `unsupported_semantics`, `unresolved_reference`, `not_applicable`, and `supported_failure`. A candidate needs supported passes within one complete declared alternative; an all-pathways exclusion needs evidenced supported failures in all declared alternatives, without unresolved checks. Outside coverage produces investigation. Every evaluation is scoped to the supplied placement: failure does not establish that no other placement or design works. Approval and remaining scope exclusions travel with the result.

`BoundaryBundle` provides optional reference checks when complete payloads are available; it is not a storage format or import workflow. It checks source/rule and input/release references and CRS consistency. Persistence must still enforce immutable revision IDs, content integrity, transactional publication, and referential integrity; Pydantic alone cannot do so.

## Verification and handoff

SR-09 adds a separate `app.spatial.payloads.SpatialImport` (`sr-09.v1`) boundary
for raw Esri XY/XYZ rings and query-scoped geometry diagnostics. It does not widen
or silently coerce SR-04 legal `Geometry`. Its reader, collection revision identity,
source links, explicit CRS conversion and `0003` storage migration are documented
in [the spatial handoff](spatial.md). It cannot substitute for reviewed site facts
or be used as an accepted dataset/evaluation result.

Run focused, database-free tests with `python -m unittest discover -s contract_tests -p test_contracts.py -v`. The fixtures cover every root boundary, JSON round trips, malformed/extra/versioned payloads, percentage and FSR bases, unit equivalence, missing design facts, geometry/CRS errors, unresolved references and comparisons, exact operators, extraction failures, incomplete alternatives, evidence-free exclusions, and failed placements. They do **not** establish extraction accuracy or legal interpretation. The foundation PR replaced the historical database suite with isolated tests; `uv run --locked pytest -q` now runs both foundation and contract tests.

| SR-04 acceptance area | Verification status |
|---|---|
| Typed source, design, site/placement, candidate/accepted-rule, release and result payloads | Covered by construction and JSON round-trip tests. |
| Original and normalized quantities, ratio bases, physical/regulatory separation | Covered by percentage, FSR, unit-equivalence, domain and missing-definition tests. |
| Extraction failure, missing facts, unsupported logic, outside coverage and scoped supported failure | Covered by negative and state-preservation tests. |
| Evidence locators, revision identities, schema versions and unknown effective dates | Covered structurally; correct legal source support remains a reviewer task. |
| Coherent alternatives, approval, scope, failed placement, geometry provenance | Covered by release/result and geometry reference tests; actual fit remains unverified. |

The focused suite contains 14 tests. Foundation integration declares Pydantic 2 directly in the locked dependencies, includes `contract_tests` in default pytest discovery, and lints the contract tests in CI. The combined suite passes 37 tests locally on Python 3.12; `uv run --locked ruff check app tests contract_tests` passes.

SR-05 should supply real captured bytes, original GIS CRS/units, source-effective-date evidence, manufacturer specifications, and reviewed site geometry. URI conventions and stable IDs need a shared decision before capture. SR-08 should store exact validated payload versions as immutable revisions, map ambiguous splits/merges by review decision, retain raw failed extraction references, and enforce that active releases never point to missing revisions. Future payload changes need a new schema version and an explicit reader/migration compatibility policy; consumers should reject unsupported versions. SR-10 must compute results under reviewed semantics and cannot treat these synthetic result fixtures as an evaluator oracle. The integrated foundation manifest and CI now gate SR-04 with the direct Pydantic dependency and contract test discovery.

Unresolved decisions: the pilot's actual use/approval pathway; regulatory area and height definitions; threshold inclusivity and overlapping intervals; which conditional clauses merit executable support; CRS/geometry quality policy; site identifiers and source reuse rights; and how much alternative-level coverage is required for a final result. Revisit the model after SR-05/SR-06 evidence rather than treating the provisional enum sets as universal.
