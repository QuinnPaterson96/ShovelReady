# SR-33: Inspect computed draft evaluations in the app

Status: Ready for dispatch (2026-09-24)
Milestone: M1 preparation
Parents: SR-12, SR-13; does not complete accepted screening
Dependencies: Existing sr-10.v1 report for development; SR-32 for combined live demo
GitHub issue: https://github.com/QuinnPaterson96/ShovelReady/issues/66

## Problem and outcome

The app shows spatial observations and authored fictional outcomes, but does not show
reports produced by the evaluator. Add a clearly labelled draft-evaluation mode that
consumes the SR-32 read-only API and lets a user inspect the actual check traces.

## Acceptance criteria

- [ ] Add a distinct optional mode, preserving the observation, historical public-case
  and existing fictional preview modes. Its heading states that these are synthetic
  examples computed by the evaluator, with draft data and no published zoning release.
  Describe a passing arithmetic example within its declared scope, never as an actual
  buildable site, legal approval or accepted dataset.
- [ ] Select the three agreed aliases (`synthetic-direct-pass`,
  `synthetic-missing-fact`, `synthetic-placement-failure`) and fetch
  `GET /api/draft-evaluations/{case_id}`. The success body is the unwrapped existing
  `EvaluationReport` (`sr-10.v1`, `bounded-scalar.v1`, `draft_only`). No frontend
  evaluation, manufactured result, fake release ID or fallback to authored preview
  outcomes when the API is unavailable.
- [ ] Validate the boundary using a schema derived from the current Pydantic report
  and explicit semantic/identity checks where needed. Keep decimal values as strings
  for faithful display. Loading, unavailable/disabled, missing case, incompatible data
  and network-error states are visible; switching cases cannot display a stale response
  or stale evidence as the newly selected case.
- [ ] Show all alternative/check outcomes, diagnostics and scope exclusions. Keep
  approval separate from arithmetic; a failed supplied placement must not imply that
  no placement on the parcel can work. Missing facts, unresolved regulatory references
  and out-of-coverage scope remain distinguishable.
- [ ] Expose exact design, site, placement, rule, fact/binding and draft revisions,
  evaluator/schema version, measurement definition, original and normalized quantity
  with ratio basis, evidence excerpt/context, source hash/capture/effective-date state,
  and actual review scope. A synthetic review is labelled as such, not human approval.
  Use readable summaries with expandable detail rather than a wall of identifiers.
- [ ] Render evidence as inert text. Do not link filesystem/private/repository URIs as
  if they were downloadable documents. Make full-source availability explicit; do not
  build a generic document server or claim H1/H2 from the virtual pilot are proven bugs.
- [ ] Add meaningful boundary/presentation tests for all three outcomes, unresolved
  alternatives, optional/missing rule/fact bindings, unknown versions, unsafe evidence
  and fetch failure/stale selection. Test data must be generated by the current Python
  evaluator from labelled invented requests, with generator/version documented; do not
  hand-author successful report conclusions. Keep existing frontend tests running.
- [ ] Run frontend tests, typecheck and build. Record what was verified with fixtures
  versus the live backend; integrated browser acceptance waits for SR-32. In a short
  task-owned handoff, give exact demo instructions and remaining integration checks.

## Ownership and handoff

Own `frontend/src/draft_evaluations/`, frontend test fixtures/schema generation,
`frontend/src/App.tsx`, necessary styles, frontend test discovery/package changes,
and `docs/draft-evaluation-ui.md`. Do not modify backend, shared Python contracts,
migrations, central docs/backlog, original preview controls or QA grading data.
Preserve source and report identities through rendering. The Python evaluator is the
sole owner of outcomes. Use [the shared handoff](wave-seven-prompts.md) for endpoint
details and dependencies. Open a PR; do not self-merge or close parent issues.
