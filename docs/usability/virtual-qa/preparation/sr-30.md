## Proposed counting rules

Freeze required checks, critical flags, mode, expected observable evidence and rubric
revision before dispatch. Count each check once per attempt; split compound checks
before a future run, never silently rescore SR-26 with a new checklist. Keep original
grades when correcting a rubric. Retried runs are linked attempts, not replacements.
Report raw numerator/denominator, case, category and severity (including unknown),
separately for task and detection modes and distinct rubric/control revisions.

| Metric | Exact proposed numerator / denominator and exclusions |
|---|---|
| Task checklist outcomes | For each status (supported, partial, unsupported, not attempted, unassessable), count / all applicable frozen required check-attempts in task mode. Also show supported / assessable required check-attempts; assessable includes partial, unsupported and not attempted, excludes unassessable. Partial earns no fractional success. Explicitly inapplicable checks are listed with reasons outside both denominators. |
| Critical omissions | Absent required critical check-attempts / assessable applicable critical check-attempts. For a partial compound check, count one omission only if a frozen critical component is absent. Wrong affirmative answers count as unsupported, not also absent. A tool-blocked check is unassessable, not an omission. Report noncritical omissions separately. |
| Unsupported conclusions | Adjudicated unsupported distinct substantive claim-attempts / assessable distinct substantive claim-attempts in submitted reports. Include unsolicited claims, collapse paraphrases within an attempt, exclude missing/disputed evidence from this denominator and show its count separately. No submitted claims gives N/A, not perfect accuracy. |
| Confirmed finding precision | Adjudicated confirmed actionable app-defect allegations / adjudicated app-defect allegations (confirmed plus rejected). Pending/disputed allegations stay outside the denominator with counts; data gaps and hypotheses are not app-defect allegations unless presented as bugs. Unit is one stable cause/check allegation per attempt, retaining cross-run repeats. Also report unique causes separately. |
| Seeded-fault detection | Observable seeded fault-attempt opportunities correctly identified with supporting evidence / all valid observable seeded fault-attempt opportunities in detection mode. A participant overlooking an available fault remains a miss; independently demonstrated environment/materialization failure excludes that opportunity with a blocked count. Match fault identity, not vague bug language; one hit per fault per attempt. |
| Clean-control false alarms | Valid assessable clean-control detection attempts with at least one adjudicated false app-defect allegation / valid assessable clean-control detection attempts with resolved allegations (including completed attempts with no allegation). Unresolved allegations or missing report/evidence make the attempt pending/unassessable, not a clean success. Report allegation counts as well. |
| Blocked/unassessable attempts | Attempts blocked or containing at least one unassessable required check / all started attempts, separately by mode; also list completed, timed-out and blocked statuses. Pre-dispatch failures are listed separately, not invented participant attempts. |
| Review effort | Recorded reviewer minutes / attempts with complete review timing; also minutes / adjudicated findings only when time is explicitly attributable to those findings. Report total known minutes, timed/untimed review counts and reviewer role. Unknown timing is never zero; no human effort estimate from agent wall time. |

Every zero or unknown denominator produces N/A with a reason. Unknown-defect recall
is always N/A. No pooled overall score, population accuracy or human usability claim.
SR-26 alone supplies no seeded opportunities, reviewed clean-control attempts, or
human timing; those metrics are N/A. Evidence availability must not be inferred from
participant success: retain blocked/pending counts alongside every eligible subset.

## Adjudication and deduplication

Validate identities and evidence pointers before semantic grading. Exact identifiers
can be checked deterministically; numeric comparisons need a frozen unit/basis and
rounding policy. Missing evidence makes a claim unassessable unless retained evidence
actually contradicts it; an invalid pointer cannot prove either success or a defect.
Keep initial judgments and later decisions as separate revisions with supporting and
contradicting evidence, reviewer identity/role, date, rationale and superseded decision.
Saved model suggestions are suggestions; disclose when no human participated and do
not let a model approve its own unsupported interpretation. Disagreement alone does
not establish legal truth. Reproduce an alleged app defect on the pinned app/data/
fixture variant before an actionable local bug draft; preserve tool failures, agent
errors, source gaps and usability hypotheses as distinct dispositions.

Group by stable cause plus affected check and compatible app/data/variant scope,
not prose similarity. Preserve every occurrence's run and evidence; unknown causes
remain separate until reviewed. Never merge a seeded variant fault with a baseline
defect merely because symptoms match. A rubric correction is a new grade revision,
not a new incident. Prefer a linked existing issue's update draft when the cause
matches. Withhold pending/disputed/unreproduced bug drafts. A qualified draft needs
identities, observed/expected evidence, reproduction steps, severity, acceptance
criteria and regression layer; publication remains a separate integration action.
