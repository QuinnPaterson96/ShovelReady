# SR-22: Standardize short PR handoffs and integration reconciliation

Status: Ready for implementation (September 24, 2026)
Milestone: M1: Technical proof support
Dependencies: None; parallel with SR-20/SR-21/SR-23
GitHub issue: https://github.com/QuinnPaterson96/ShovelReady/issues/37

## Outcome

A reviewer can understand, verify and demonstrate a change without reconstructing task history. Handoff documentation remains concise and distinguishes partial implementation from completion of the parent MVP objective.

## Scope and acceptance criteria

- [ ] Add `.github/pull_request_template.md` covering problem/result, linked ticket and satisfied criteria, base/head provenance, interface/config/migration changes, exact verification commands/results/skips, a demo command where relevant and remaining limitations/dependencies.
- [ ] Keep fields brief and allow explicit not-applicable answers. Do not require elaborate boilerplate for documentation-only changes or duplicate historical handoffs. Base/head provenance can refer to GitHub's PR head, avoiding a self-referential commit SHA requirement.
- [ ] Add a short AGENTS instruction to use the handoff, declare shared-file ownership before parallel work and preserve evidence categories. Do not weaken existing identity, database, source-review or publication rules.
- [ ] Add a compact integration checklist to `docs/quality.md` covering review of actual code and interfaces, appropriate combined checks, final-head required CI, central README/architecture/backlog reconciliation and honest partial-ticket status. Preserve the existing definition of done.
- [ ] Rehearse the template against one merged implementation PR and one docs-only PR; record whether another reader has enough information to reproduce the claimed check. Do not invent missing historical commands or claim an independent reader test. No new tests are required for this documentation-only change.

## Ownership and exclusions

Own `.github/pull_request_template.md`, `AGENTS.md`, the relevant handoff section of `docs/quality.md` and a short `docs/pr-handoffs.md` worked example if useful. SR-20 owns CI; SR-21 owns demo/UI/local-development docs. Central backlog/README status updates remain integration-owned. Do not edit or comment on other contributors' PRs, add required reviewers/bots, impose new approval gates, change branch protection or create new orchestration infrastructure.

## Delivery

Use branch `codex/pr-handoff-template` in this task's managed worktree. Verify personal author/committer and Git/gh identity, commit explicit paths, push and open a PR without merging. State what was checked and keep the PR itself an example of the proposed handoff.
