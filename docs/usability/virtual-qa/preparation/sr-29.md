## Reuse and limits established by source inspection

- [LocalDatabase](../../../../scripts/local_database.py) already provides explicit
  start/status/migrate/seed/stop operations, an exclusive operator lock, loopback
  checks, root/configuration matching and PostgreSQL system-identifier checks.
  Running operations verify the actual server before changing or stopping it.
  Initialization refuses foreign nonempty directories; interrupted initialization
  is retained for diagnosis. It has no deletion operation or run ownership ledger.
- Always supply a new scratch root, PostgreSQL binaries and port explicitly. The
  helper's persistent default root and default port are unsuitable for QA ownership.
  Its database name can remain unchanged inside a separate owned cluster. Its
  `local.json` contains credentials: keep it outside Git and evidence bundles.
  `execute` rejects Git-contained roots and PG environment overrides. Reusing only
  lower-level methods would lose some of these guards.
- [demo.py](../../../../scripts/demo.py) validates a clean commit before and after
  its locked frontend build, reserves the actual loopback HTTP socket through
  startup, and checks owned database configuration plus an exact spatial revision.
  It runs HTTP in the foreground; stopping HTTP does not stop PostgreSQL.
  [demo.ps1](../../../../scripts/demo.ps1) resolves configuration relative to the
  caller. Neither launcher is a process supervisor or fixture overlay interface.
- The launcher always needs the licensed spatial DB and fixes its collection to
  `victoria-pilot-three-leads`. The [synthetic preview](../../README.md) needs no DB;
  [create_app](../../../../app/main.py) accepts a frontend build directory. A small
  runner-owned database-free launch path may reuse those existing primitives and
  socket/identity checks; it must not silently change the demo helper or inherit a
  configured database URL. Ignored files/toolchains remain outside Git cleanliness.

## Proposed scratch and process ownership

Require separate explicit output and scratch locations, reject default/shared
locations, and allocate exclusive per-attempt children. Keep retained evidence and
private facilitator material outside the served build. Pin baseline app/frontend
commits and data kind/revision before preparation; never adopt an existing preview.
Resolve and check path containment before writes and cleanup, including Windows
junction/reparse-point escapes. An output directory or generic helper owner marker
alone does not prove that a cluster belongs to this attempt.

Track the exact resources created by the attempt. Start only loopback listeners;
an occupied port is a refusal, not permission to kill its owner. Retain process
handles and launch identity rather than relying on a reusable PID or port alone.
Use helper ownership/server validation for DB shutdown. On success or failure,
stop only verified owned processes, confirm exit/stopped status, then consider
deleting verified scratch children. Preserve artifacts and uncertain/partial
resources with a visible cleanup failure; never reclaim stale locks blindly.
These additional runner guards and failure paths are proposals, not tested behavior.

## Proposed selection and budget bookkeeping

Use the integrated SR-27 records without creating a competing schema. Plan before
materialization: filter eligible category/split/mode groups, exclude reserved groups,
sort stable IDs/revisions, then apply a versioned seeded algorithm using the standard
library. Keep paired/group membership together across splits. Freeze exact selected
IDs, case/fixture/rubric revisions, seed, filters and algorithm identity. Fixed baseline
selection is explicit; an insufficient pool fails visibly rather than broadening it.
Repeatable selection says nothing about deterministic participant answers.

The pilot ceiling is 16 sequential sessions: five scenarios twice in task mode plus
three clean/fault pairs in detection mode. Reserve an attempt before handoff, permit
only one active participant, and retain failed/cancelled/timed-out attempts. Each
retry is a linked new attempt consuming remaining budget; no silent retry or reset.
Each session stops at ten minutes or 60 browser actions, whichever comes first.
A manual adapter can issue facilitator stop instructions and ingest actual timing/
action evidence; it cannot claim automatic interception or enforcement. Missing
counts, model/tool/cost metadata and enforcement evidence stay unknown with reasons.
Retain the original note and evidence pointers, validate on ingest, refuse overwrite,
and keep invalid environments/tool failures distinct from completed tasks.
